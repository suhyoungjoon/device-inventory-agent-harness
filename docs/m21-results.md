1차에서 기대와 달랐던 점:
- 이상적 분석가(가짜 LLM)는 4개를 다 찾았지만 실제 분석 에이전트는 고정 흐름에서 1~2개만 찾았다. 실제 분석은 코어 집계 도구(발주 **실패** 사유)부터 보고, 결품은 실패가 아니라서 P1처럼 결품으로만 드러나는 구간을 놓쳤다.

## 4. 해석과 다음 손볼 곳

1. **도메인이 "무엇이 문제인지"를 도구로 알려 주는 것이 컸다.** 코어 분석 프롬프트는 그대로 두고, 재고 도메인의 분석 도구 하나와 도구 설명만 바꿔 탐지 1~2개 → 3~4개, 개선 0 → −1.4~−2.3%p가 됐다. 두 번째 도메인을 붙일 때 "코어 집계가 보는 실패"와 "그 업무의 핵심 문제"가 다르면 도메인 분석 도구가 그 차이를 메워야 한다 (도메인 팩 가이드에 넣을 교훈).
2. 1차 LangGraph 결과 보고의 목표 달성 문구가 "결품률 2.8% ≥ 목표 5.0%"처럼 낮을수록 좋은 지표에도 ≥로 나왔다. 판정은 맞았고 문구만 틀려 ≤로 고쳤다 (`core/improvement/loop.py` 1줄).
3. 발표 수치로 쓰려면 3회 이상 반복을 권한다 (고정 흐름 1회 약 $0.2, Supervisor 약 $0.9).
